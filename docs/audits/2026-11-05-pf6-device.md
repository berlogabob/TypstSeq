# PF6 device startup baseline — 2026-11-05

One cold launch was captured on the attached ELE-L29 (Android 10, arm64) with
the release-signed profile APK. `adb install -r` preserved the installed
production package and its vault. Before launch the app was force-stopped and
allowed to settle for three seconds; Android reported `LaunchState: COLD`.
The app opened the existing 10,067-note vault. No vendored files were seeded
or edited for this run.

| Measurement | Result |
| --- | ---: |
| Android activity launch (`am start -W`) | 2,275 ms |
| `open-start` | 1,468 ms after process start |
| `fast-path-done` | 1,592 ms |
| cached index published | 3,188 ms |
| initial sync done | 5,340 ms |
| background scan done | 17,170 ms |
| process PSS when sampled after startup | 556,431 KiB |
| process RSS high-water mark when sampled | 695,240 KiB |

The background scan reported 6,501 ms in `list-stat`, 1,836 ms in
`scan-finalize`, and 294 ms in validation. The CPU profile helper connected to
the profile app's VM service, but `getCpuSamples` failed with `Profiler is
disabled`; a later `top` snapshot showed 3.3% CPU and is not a startup CPU
measurement. Flutter frame timings and Dart/native channel operation counts
were not collected. The startup trace has no vendored-package count or
package-ready mark, so this vault cannot be classified as a 0-file case.

These values are a single baseline on a live vault, not a controlled
comparison. Do not compare them with the planned 0/100/1,000-file cases or use
PSS as Dart heap: the sample includes the Android process and native mappings.
