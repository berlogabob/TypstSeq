# TyLog UX/UI and design-system audit — 2026-10-08

What this repo does: TyLog is a Flutter app for local notes, tasks, journals, articles and linked knowledge, with optional cloud sync. This audit assumes one person using a large vault on a narrow phone or desktop, including larger system text.

Scope: source inspection of `lib/`, relevant `packages/tylog_core` contracts, and UI tests. Graphify queries ran first; source confirmed every finding below. `graphify-out/wiki/index.md` is absent. No app, tests, phone, adb, network or external vault was used. Only this report was written. Findings describe source-confirmed behavior; width/scale failures are deductions from layout constraints, not observed screenshots. The existing dirty graph report was left alone. No graph update is needed because no code changed.

### Dark mode and text scaling

**Dark mode is broadly honoured.** The app restores system/light/dark preference and uses brightness-specific colour schemes (`lib/app_mobile.dart:149`, `lib/app_mobile.dart:194`, `lib/app_mobile/vault_lifecycle.dart:19`). Graph edges and document highlights have explicit dark variants (`lib/graph.dart:1396`, `lib/rich_editor/document_model.dart:101`). Reader night mode reuses the dark scheme (`lib/widgets/reading_mode.dart:248`). Reader system-bar icons have a mismatch, finding 20.

**Text scaling is partly honoured.** Normal Flutter text inherits the system scaler. Reader font preference composes with it rather than replacing it (`lib/widgets/reading_mode.dart:292`, `lib/widgets/reading_mode.dart:450`). Canvas graph labels omit it, finding 18. Fixed-height chip/strip layouts and wide trailing controls constrain larger text, findings 8–11. `CompactDateTitle` deliberately shrinks text to fit (`lib/widgets/date_format.dart:55`); this can reduce the visible benefit of larger text in the app bar.

Existing guards cover brand seed, palette colours, radius use in selected UI paths and kind icons (`test/design_tokens_test.dart:41`, `test/design_tokens_test.dart:54`, `test/design_tokens_test.dart:69`, `test/design_tokens_test.dart:87`). Contrast tests cover warning and graph edges in both themes (`test/contrast_test.dart:50`). They do not establish that every rendered surface is accessible. Tests were inspected, not run.

## Part B — Ranked findings

Severity: **high** risks unsaved work or interrupts the main writing flow; **medium** prevents recovery, hides state or makes a common action/layout inaccessible; **low** adds friction or design drift. Rank follows user impact, not implementation size.

1. **High — Autosave failure is normally invisible.** After an index is loaded, a failed save leaves only the dirty dot while navigation may silently refuse to proceed. **Evidence:** `lib/workspace_controller.dart:648` records `Save failed`; `lib/app_mobile.dart:4901` recognises only `Open failed`, and `lib/app_mobile.dart:4919` shows ordinary status only during indexing; `lib/app_mobile.dart:4091` aborts navigation on save failure. **Smallest fix:** include save failures in the existing floating error banner with Retry Save; retain the dirty state.

2. **High — Cancelling first-time vault selection leaves an editable document that cannot be saved.** The user can type into the normal editor without a vault and sees no choose-folder state in the body. **Evidence:** `lib/app_mobile/vault_lifecycle.dart:22` returns after setting a choose-folder status; `lib/app_mobile.dart:4580` still builds `TyLogRichEditor`; `lib/rich_editor/editor_widgets.dart:884` has no disabled/read-only guard; `lib/workspace_controller.dart:614` refuses saving; `lib/app_mobile.dart:4901`/`lib/app_mobile.dart:4919` do not display this no-vault status. **Smallest fix:** render a choose-vault empty state with a button in place of the editor until a vault is open.

3. **High — A note can switch editor implementations while the user is typing.** Crossing 32KiB/200 blocks, or changing a plain block into formatted content, changes the widget type on a shell rebuild and loses its active field/focus. **Evidence:** `lib/rich_editor.dart:35` derives the choice from live content; `lib/app_mobile.dart:372` recomputes it; `lib/app_mobile.dart:4571` switches between `VirtualPlainEditor` and `TyLogRichEditor`; `lib/app_mobile.dart:691` rebuilds the shell after workspace notifications. **Smallest fix:** choose the editor once when opening a note and keep it for that editing session.

4. **Medium — A failed journal read stays a loading bar forever.** The completed error snapshot has no data, so the failure follows the loading branch and offers no retry. **Evidence:** `lib/widgets/journal_feed.dart:222` reads storage; `lib/widgets/journal_feed.dart:253` checks only `hasData` and returns progress at line 258. **Smallest fix:** check `snapshot.hasError` first; show a short error and retry that evicts the failed cached future.

5. **Medium — Main Search failures have no visible error or retry state.** Keyword/vector exceptions escape the unawaited query, leaving previous results or an apparent no-match state. **Evidence:** `lib/knowledge_screen.dart:238`, `lib/knowledge_screen.dart:243` await queries outside the citations-only catch; `lib/knowledge_screen.dart:264`/`lib/knowledge_screen.dart:268` launch unawaited; the empty row at `lib/knowledge_screen.dart:550` offers only no matches/indexing. **Smallest fix:** catch the main query failure, retain the typed query, and show a retry row; track pending queries so they do not look like completed empty results.

6. **Medium — Sync dashboard refresh failure is hidden once any snapshot exists.** The screen can show stale sync state even though its reload failed. **Evidence:** `lib/widgets/sync_dashboard.dart:128` stores `loadError`; `lib/widgets/sync_dashboard.dart:260` renders it only when `data == null`. **Smallest fix:** show a floating reload-error banner above existing data, with Retry and a stale-data label.

7. **Medium — Editing metadata destroys the document's undo history and moves its caret to the end.** A title/tag change should not discard the ability to undo earlier prose edits. **Evidence:** `lib/app_mobile.dart:1514` calls `_loadSource`; `lib/app_mobile.dart:959` calls `loadSource`; `lib/rich_editor/editing_controller.dart:101` collapses selection at the end and lines 105–106 clear undo/redo. **Smallest fix:** update the existing document prefix from the new header while preserving body, selection and undo; reserve `loadSource` for opening/replacing documents.

8. **Medium — Article rows let trailing controls consume the title's width.** Progress text/bar, two 48dp property controls and More share an unbounded trailing `Row`, so narrow widths or large text can leave no room for the title. **Evidence:** `lib/widgets/work_surface.dart:1488`, `lib/widgets/work_surface.dart:1503`, `lib/widgets/work_surface.dart:1512`, `lib/widgets/property_select_chip.dart:115`. **Smallest fix:** keep More in the trailing slot and move property controls/progress into the subtitle or existing action sheet on narrow layouts.

9. **Medium — Library filters are pinned above the list and can crowd out results.** Articles have search plus two wrapping filter bands; Tasks has filters plus search; Notes has a fixed 48dp kind band that also receives top padding. **Evidence:** `lib/widgets/work_surface.dart:288`, `lib/widgets/work_surface.dart:329`, `lib/widgets/work_surface.dart:614`, `lib/widgets/work_surface.dart:959`, `lib/widgets/work_surface.dart:1085`, `lib/widgets/work_surface.dart:1107`. **Smallest fix:** keep one compact active-filter row and put secondary filters behind the existing menu, or move them into the list's scrollable header; remove the fixed chip-band height.

10. **Medium — Entity metadata can consume the entire editor viewport.** The non-scrollable header renders every property before the expanded editor, including on short screens with a keyboard. **Evidence:** `lib/widgets/entity_header.dart:39`, `lib/widgets/entity_header.dart:77`; shell places it outside the editor at `lib/app_mobile.dart:4753`. **Smallest fix:** collapse aliases/tags/properties behind a disclosure and keep only identity visible above the editor.

11. **Medium — Daily idea and screenshot strips take substantial writing space outside the editor scroll.** When present, they reserve 88dp and 116dp plus headings above the editor, in addition to Today's agenda area. **Evidence:** `lib/app_mobile.dart:4815` builds them before `Expanded`; `lib/widgets/idea_hub.dart:131`, `lib/widgets/screenshot_strip.dart:92`; Today permits another 45% header region at `lib/widgets/work_surface.dart:126`. **Smallest fix:** collapse each strip behind a single row or put it into the existing collapsed agenda, preserving access without permanently reserving both carousels.

12. **Medium — Sync progress pushes dashboard content down.** Starting/stopping a sync inserts/removes progress, stage text and gaps at the start of the `ListView`. **Evidence:** `lib/widgets/sync_dashboard.dart:271`. **Smallest fix:** use a `Stack` and float the progress/stage indicator over the dashboard; the shell already uses this pattern at `lib/app_mobile.dart:4954`.

13. **Medium — Async idea history pushes the daily editor after loading completes.** Its widget changes from zero height to a heading and carousel inside the parent column. **Evidence:** `lib/widgets/idea_hub.dart:118`, `lib/widgets/idea_hub.dart:122`, `lib/widgets/idea_hub.dart:123`; placement at `lib/app_mobile.dart:4815`. **Smallest fix:** keep a stable collapsed disclosure row while loading; reveal history only when the user expands it.

14. **Medium — Calendar day targets fall below 48dp on narrow screens.** Seven square cells divide the available width, without a minimum hit size; a 320dp screen inside the shell and calendar padding leaves about 39dp per cell. **Evidence:** `lib/month_calendar.dart:97`, `lib/month_calendar.dart:125`; shell side padding `lib/widgets/work_surface.dart:28`; calendar side padding `lib/widgets/calendar_tab.dart:64`. **Smallest fix:** remove nested horizontal padding around the calendar; when width is still below 336dp, use a horizontally scrollable grid with seven 48dp columns.

15. **Medium — Protected inline links/chips have text-sized tap targets.** Their InkWell contains only one-pixel vertical padding and has no minimum interactive height. **Evidence:** `lib/rich_editor/editor_widgets.dart:1824`, `lib/rich_editor/editor_widgets.dart:1829`. **Smallest fix:** apply the existing `kMinTapTarget` constraint to interactive chips, keeping the label compact within it; check line spacing because the target adds height.

16. **Medium — The running-task title has a short tap target.** The title's InkWell is only as tall as one line of text; the adjacent Stop button's height does not enlarge that child's hit box. **Evidence:** `lib/widgets/task_clock.dart:93`, `lib/widgets/task_clock.dart:96`. **Smallest fix:** constrain the title InkWell to a minimum height of `kMinTapTarget`.

17. **Medium — Calendar cells omit accessible date and state labels.** A screen reader gets a day number without month/year, selected/today state or the meaning of the markers; double-tap-to-open is also unexplained. **Evidence:** `lib/month_calendar.dart:125`, `lib/month_calendar.dart:136`, `lib/month_calendar.dart:160`, `lib/month_calendar.dart:167`. **Smallest fix:** wrap cells in `Semantics` with full date, selected state and marker summary, and expose opening the journal as an explicit action.

18. **Medium — Graph and Voronoi labels ignore system text scaling.** Their `TextPainter`s size labels from canvas geometry and never receive the user's scaler. **Evidence:** `lib/graph.dart:1195`, `lib/graph.dart:1318`; `lib/voronoi_view.dart:540`; geometry ladder `lib/widgets/graph_label.dart:42`. **Smallest fix:** pass `MediaQuery.textScalerOf(context)` into the existing painters and `TextPainter`s; use the scaled measurements for label collision/fit checks.

19. **Medium — Backlink disclosure omits its expanded/collapsed accessibility state.** Its custom InkWell toggles visibility but exposes only text and a changing icon. **Evidence:** `lib/widgets/linked_references.dart:88`, `lib/widgets/linked_references.dart:102`, `lib/widgets/linked_references.dart:107`. **Smallest fix:** add `Semantics(button: true, expanded: _expanded)` around the header, or use native `ExpansionTile` if it preserves the bounded list.

20. **Medium — Reader system-bar icons can use dark ink over a dark app theme.** With app dark mode and reader night toggle off, content inherits a dark theme while icon brightness still follows only the night toggle. **Evidence:** `lib/widgets/reading_mode.dart:248`, `lib/widgets/reading_mode.dart:257`, `lib/widgets/reading_mode.dart:265`, `lib/widgets/reading_mode.dart:268`. **Smallest fix:** derive both system-bar brightness values from `readingTheme.brightness`.

21. **Medium — Doing/cancelled task states are hidden behind a long press.** Tap changes only done/todo, while the tooltip is manual and never shown by this row. **Evidence:** `lib/widgets/task_row.dart:94`, `lib/widgets/task_row.dart:98`, `lib/widgets/task_row.dart:103`; menu choices `lib/widgets/task_fields.dart:25`. **Smallest fix:** show the existing status menu on a secondary visible menu action and announce the current state in the tooltip/semantics; retain quick done/todo tap.

22. **Medium — Dismissing the template picker still creates a blank note.** Null means both explicit Blank note and barrier/back dismissal, so cancellation continues creation. **Evidence:** `lib/app_mobile.dart:1354` does not distinguish cancellation; `lib/app_mobile.dart:1384`, `lib/app_mobile.dart:1390` return null for blank. **Smallest fix:** put the template choice in the existing title dialog, with an explicit blank value and cancellation aborting the whole dialog.

23. **Medium — Tapping Sync can wait on storage before any screen acknowledges the tap.** Reading conflict records occurs before pushing the dashboard, and exceptions have no local UI handler. **Evidence:** `lib/app_mobile.dart:2894`, `lib/workspace_controller.dart:1591`. **Smallest fix:** push the existing dashboard immediately and refresh conflicts inside its guarded load flow so its loading/error states cover the work.

24. **Medium — Routine failures expose raw exception strings.** Users see technical class/path details instead of a concise explanation and recovery action. **Evidence:** editor `lib/app_mobile.dart:973`; task mutation `lib/app_mobile.dart:1990`; first open `lib/app_mobile/vault_lifecycle.dart:85`; folder inspection `lib/app_mobile/vault_lifecycle.dart:284`; Nextcloud `lib/widgets/nextcloud_connect_dialog.dart:105`; screenshot settings `lib/widgets/screenshots_settings.dart:70`; dashboard `lib/widgets/sync_dashboard.dart:264`. **Smallest fix:** use short action-specific messages, use existing `friendlySyncError` for sync failures, and move raw details into the existing diagnostics/help surfaces. Keep Typst compiler details available in Source/Explain error.

25. **Medium — Calendar settings rejects invalid values without explaining the problem.** Save & refresh silently returns for a bad URL or non-positive refresh interval, so the form appears unresponsive. **Evidence:** `lib/widgets/settings_sheet.dart:131`, `lib/widgets/settings_sheet.dart:136`; the fields at `lib/widgets/settings_sheet.dart:111` have no error text. **Smallest fix:** retain the validation and show the failed field's error using native `InputDecoration.errorText`; keep the dialog open with the user's input.

26. **Medium — Voronoi computation failures have no user-facing recovery state.** Initial or child-cell layout errors only reach Flutter's error reporting, leaving loading or incomplete map content without an explanation. **Evidence:** `lib/voronoi_view.dart:177`, `lib/voronoi_view.dart:294`; rendering at `lib/voronoi_view.dart:382` only checks whether cells exist. **Smallest fix:** store the failure in this widget and show Retry over the current map or in place of its loader; restart the existing computation on retry.

27. **Low — UI copy has no app localization setup and contains mixed-language hints.** English navigation and settings remain literal while the task date hint combines English and Russian. **Evidence:** `lib/app_mobile.dart:183` configures no localization delegates/locales; navigation `lib/app_mobile.dart:5158`; `lib/widgets/task_fields.dart:72` uses `today / завтра / +3d`. **Smallest fix:** first make the hint match the current UI language; reuse installed `intl` for dates. Translation coverage needs an agreed language scope, not a new package. The English-only date helper is a documented limit (`lib/widgets/date_format.dart:27`), not a separate bug.

28. **Low — Notes uses “No notes yet” for an empty filter result.** A populated vault with an empty selected kind is presented like a new vault. **Evidence:** kind filtering `lib/widgets/work_surface.dart:606`; empty message `lib/widgets/work_surface.dart:663`. **Smallest fix:** distinguish an empty collection from “No notes match this kind”, and let that message clear the filter.

29. **Low — Note picker has no no-match row.** Typing a query with no matches leaves a blank list, or only a create action unrelated to the missing results. **Evidence:** `lib/widgets/note_picker_sheet.dart:46`, `lib/widgets/note_picker_sheet.dart:74`, `lib/widgets/note_picker_sheet.dart:82`. **Smallest fix:** add a native `ListTile` saying no matches when `filtered.isEmpty`.

30. **Low — Saving a search opens a modal for one small inline name field.** It interrupts the results screen for a reversible metadata action. **Evidence:** `lib/knowledge_screen.dart:421`, `lib/knowledge_screen.dart:425`. **Smallest fix:** replace the Save chip temporarily with an inline name field and save/cancel actions; do not add another permanently visible bar.

31. **Low — Saved-search deletion bypasses the shared destructive confirmation style.** Its Delete is an ordinary TextButton while article/vault confirmations use the shared destructive treatment. **Evidence:** `lib/knowledge_screen.dart:283`; `lib/widgets/dialogs.dart:26`; article usage `lib/app_mobile.dart:2831`. **Smallest fix:** replace the duplicate dialog with `showConfirmDialog(destructive: true)`.

32. **Low — Dialog field borders are defined twice instead of in the theme.** The app-wide borderless default makes each dialog field recreate an outlined border. **Evidence:** `lib/app_mobile.dart:190`, `lib/app_mobile.dart:5256`, `lib/widgets/nextcloud_connect_dialog.dart:132`. **Smallest fix:** make the theme's default outlined; explicitly keep editor/picker fields borderless where intended. Keep password/autofill behavior intact.

33. **Low — Some plain snackbars bypass the existing shared helper.** This creates multiple places to change message duration or presentation. **Evidence:** `lib/widgets/snack.dart:4`, `lib/widgets/screenshots_settings.dart:68`, `lib/app_mobile/markdown_import_flow.dart:359`. **Smallest fix:** call `showSnack` in screenshot settings; retain the relink caller's nullable messenger behavior until a scaffold is guaranteed.

34. **Low — Repeated spacing and motion values are still scattered through the UI.** A common inset or editor motion change needs multiple edits despite the existing token file. **Evidence:** shell `lib/widgets/work_surface.dart:28`; editor `lib/widgets/editor_panel.dart:78`; settings `lib/widgets/settings_sheet.dart:168`; docks `lib/widgets/editor_panel.dart:88`, `lib/rich_editor/editor_widgets.dart:1300`. **Smallest fix:** add only the repeated spacing and motion constants listed in Part C to `constants.dart`, then replace duplicates in the busiest files.
