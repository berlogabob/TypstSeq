# TyLog codebase audit — 2026-10-08

What this repo does: TyLog stores journal and knowledge notes as Typst files. Flutter provides editing, search, and optional Nextcloud sync; SQLite stores a projection and revision history. This audit assumes one person, several devices, and a vault with thousands of notes and large attachments.

Read-only audit of `lib/`, `packages/tylog_core`, and tests, with the Android background worker read to confirm its completion contract. Only this report was written. No phones, adb, network, external vaults, builds, or tests were used.

Navigation started with `graphify query "save sync vault workspace_controller rich_editor database background service"`. Focused `explain NextcloudSync` and `query "backgroundSyncMain VaultLock"` followed. The first query was truncated; source reads confirmed all findings. `graphify-out/wiki/index.md` is absent. No graph update was run because this task permits only the report to change. `graphify-out/GRAPH_REPORT.md` was already dirty at the start.

`flutter analyze --no-pub`: **passed**, exit 0, “No issues found!” in 4.8 seconds. `--no-pub` avoids dependency fetching. Analyzer success does not verify the asynchronous failures below.

## Ranked findings

### Must fix

1. **High — Backgrounding can leave the last edit unsaved when sync refuses to run.**
   - Problem: With Nextcloud configured, pausing calls sync instead of saving directly. An existing sync, a held lock, or retry backoff returns before the dirty buffer is saved. If Android kills the app before its 400 ms timer fires, those keystrokes are lost.
   - Evidence: `lib/app_mobile.dart:2303`, `lib/app_mobile.dart:2312`; early returns at `lib/workspace_controller.dart:1669`, `:1687`, `:1698`, `:1702`; saving occurs only at `:1743`. The debounce is at `lib/workspace_controller.dart:607`.
   - Smallest fix: Flush `_save(syncAfter: false)` on pause regardless of cloud state, then attempt sync. Add one pause test with dirty text and blocked sync.

2. **High — Emptying a non-daily, headerless Typst file deletes its contents without a backup.**
   - Problem: A plain `notes/a.typ` containing meaningful prose is classed as disposable solely because it lacks the TyLog header. Saving an empty buffer deletes it before any revision receipt or snapshot is made.
   - Evidence: `lib/vault.dart:473`, `lib/vault.dart:481`, `lib/vault.dart:507`, especially `:512`. Existing protection tests cover headerless dailies and notes with headers at `test/empty_note_cleanup_test.dart:39` and `:68`.
   - Smallest fix: Delete the headerless non-daily exception from `_isDisposableNote`. Retain blank-file and pristine-starter cleanup. Add a non-daily prose preservation case.

3. **High — A sync that changes only formatting leaves the rich editor on the old source.**
   - Problem: Changing `hello` to `*hello*` remotely keeps the same visible text and task calls. The source controller adopts the new source, but the rich document does not. The next rich edit serializes the old styles and overwrites the remote formatting. Link targets and other non-task metadata can suffer the same mismatch.
   - Evidence: `lib/app_mobile.dart:658`, `:666`, `:679`; the reload comparison checks prefix, visible text, and task source only. Rich changes emit their document at `lib/rich_editor/editing_controller.dart:417` and `:423`; autosave uses that emitted source at `lib/app_mobile.dart:786`.
   - Smallest fix: Compare semantic inline styles and atom sources too, while retaining the existing tolerance for newline-only changes. Test a style-only remote update followed by typing.

4. **High — Keeping the remote version of an open note leaves the old editor buffer ready to overwrite it.**
   - Problem: Conflict resolution replaces the file and clears the conflict, but never adopts the resolved source into `WorkspaceController.source`. Reindexing does not update that buffer. The next edit can save the losing local version over the accepted remote version.
   - Evidence: Remote replacement at `lib/nextcloud_sync.dart:1255` and `:1264`; controller completion at `lib/workspace_controller.dart:2147` through `:2175` refreshes conflict records and the index only. The ordinary sync path explicitly adopts disk source at `lib/workspace_controller.dart:1883`; resolution has no equivalent.
   - Smallest fix: After resolving the current note, read and adopt its resolved bytes under the existing vault and edit-revision guards. Test keep-remote followed by one keystroke.

5. **High — Conflict resolution can overwrite edits made while it waits for a lock or the server.**
   - Problem: The dirty check happens once before waiting. The user can type and autosave afterward. Resolution constructs `NextcloudSync` without the normal replacement guard, so keep-remote or merge can overwrite those newer bytes. A sync snapshot is not guaranteed: matching cursor bytes deliberately skip backup.
   - Evidence: `lib/workspace_controller.dart:2100`, `:2130`, `:2147`; normal sync supplies `canReplaceLocal` at `:1793`. Resolution writes at `lib/nextcloud_sync.dart:1264` and `:1279`. Guard and backup behavior is at `lib/nextcloud_sync/conflicts.dart:4` and `:23`.
   - Smallest fix: Capture vault generation and edit revision before waiting, recheck ownership after awaits, and pass the existing replacement callback to resolution. Defer replacement if the note changed. Test typing during a blocked resolve.

### Should fix

6. **Medium — Background sync errors are reported to WorkManager as success.**
   - Problem: A failed sync prints an error and invokes the same completion callback as success. Android then returns `Result.success()`, so its retry policy cannot retry that failure; recovery waits for another scheduled run or foreground action.
   - Evidence: `lib/vault_service.dart:37`, `:39`, `:45`; `android/app/src/main/kotlin/org/tylog/tylog/VaultSyncWorker.kt:41`, `:46`, `:56`.
   - Smallest fix: Include a success boolean in the existing `backgroundDone` channel call and map failure to `Result.retry()`. Add a completion-contract test. No test reference to `vaultServiceMain` or `backgroundDone` was found in the inspected test trees.

7. **Medium — Divergent database revisions are ignored without telling the user.**
   - Problem: Receiving a divergent note or annotation returns `conflict` without applying it. The sync controller ignores that result, so the file-sync conflict count can be zero while a remote database change remains unapplied and invisible.
   - Evidence: `lib/database/tylog_database.dart:972`, `:978`, `:1015`; discarded results at `lib/workspace_controller.dart:1821` and `:1828`. The lower-level test expects conflict at `test/database/annotation_revision_sync_test.dart:79`.
   - Smallest fix: Check the returned enum and expose the existing needs-attention status with the affected entity. Keep the envelope for retry. Add a controller test that receives a divergent annotation.

8. **Medium — Editing across paragraphs removes formatting from untouched text in those paragraphs.**
   - Problem: A replacement spanning two blocks rebuilds both blocks from visible plain text. Bold, italic, heading, and list structure on the retained fragments disappear. The task guard protects tasks, but not those styles.
   - Evidence: `lib/rich_editor/document_model.dart:442`, `:489`, `:503`, `:506`, `:514`. Validation at `:1362` checks visible text and protected sources, not ordinary inline styles. Existing splice tests focus on a single formatted block at `test/rich_editor_replace_test.dart:26`.
   - Smallest fix: Retain the original styled parts before and after the replacement, using the existing part-slicing logic. Add one cross-paragraph edit with bold text outside the selection.

9. **Medium — Without ETags, a remote timestamp moving backward is treated as unchanged.**
   - Problem: A changed remote file restored with an older modification time can be skipped. The fallback checks whether the time increased, not whether it changed.
   - Evidence: `lib/nextcloud_sync/path_sync.dart:300` through `:306`; `lib/nextcloud_sync/sync_state.dart:4` through `:7`.
   - Smallest fix: Compare timestamps for inequality. Add a no-ETag case with changed bytes and an older timestamp. Same-timestamp changes still need a content check when remote metadata cannot identify a version.

10. **Medium — Every foreground sync rereads the entire revision directory inside a database transaction.**
   - Problem: Even when there are no new envelopes, sync lists, reads, decodes, and checks every historical revision file. The cost grows with history rather than this sync's changes, and storage awaits keep the transaction open.
   - Evidence: `lib/workspace_controller.dart:1809` through `:1838`; duplicate detection itself queries SQLite at `lib/database/tylog_database.dart:955`.
   - Smallest fix: Filter envelopes using the existing sync decisions and process downloaded files, plus previously failed receives; retain a full recovery pass. Read bytes before starting the database transaction.

11. **Medium — Editing repeatedly schedules a whole-vault semantic stamp scan.**
   - Problem: Every workspace notification queues semantic refresh. After the debounce, even a single-note edit reads the path and timestamp of every projected note, then starts indexing work. In-flight coalescing prevents overlap but does not prevent repeated scans after pauses in typing.
   - Evidence: `lib/app_mobile.dart:690`, `:694`, `:720`; `lib/retrieval/semantic_search_controller.dart:116`, `:137` through `:146`, `:171`.
   - Smallest fix: Queue this refresh when the saved/index revision changes, using the controller's existing revision fields. Do not trigger it for dirty/status-only notifications.

12. **Medium — Downloading a large attachment loads and hashes the entire body on the UI isolate.**
   - Problem: The network body first streams to disk, then is read into one byte buffer and hashed synchronously. Archive downloads likewise materialize an entry. Large PDFs or photos can stall foreground editing and increase peak memory.
   - Evidence: `lib/nextcloud_sync/webdav_client.dart:565`, `:571`, `:612`, `:614`, `:620`; foreground sync runs directly from `lib/workspace_controller.dart:1771` and `:1801`.
   - Smallest fix: Reuse streaming file copy and streaming digest where the storage backend permits them. For byte-only storage, do decompression and hashing in an existing worker isolate and bound transfer size. Measure on hardware before claiming a frame-time improvement.

13. **Medium — Each workspace notification rebuilds the whole app shell and rescans library lists.**
   - Problem: Editing, saving, and status updates call the parent's `setState`. Its large build recreates the work surface, whose library build filters and sorts the note collection again. Cost grows with vault size despite an unchanged library.
   - Evidence: `lib/app_mobile.dart:652`, `:691`, `:4285`; filtering begins at `lib/widgets/work_surface.dart:867`. Edit/save notifications occur at `lib/workspace_controller.dart:599` and `:645`.
   - Smallest fix: Cache filtered library results by index revision and query, using the existing revision mechanism. Let the existing dirty/status notifiers update their own widgets without rebuilding the library.

14. **Medium — Rich-editor output tests can pass on Typst that the compiler rejects.**
   - Problem: The native editor insertion test verifies source markers and parse/serialize identity. The audit and replacement tests also use the app's parser. They do not compile their emitted rich-editor output, so parser and serializer agreement is not a compiler check.
   - Evidence: `integration_test/rich_editor_native_test.dart:82`; `test/roundtrip_audit_test.dart:81`; `test/rich_editor_replace_test.dart:40`; runtime validation is the same parse at `lib/rich_editor/document_model.dart:1354`.
   - Smallest fix: Compile a small set of actual edited outputs using the existing host Typst test pattern at `packages/tylog_core/test/writer_compiles_test.dart:35`. Keep fast parser tests too.

15. **Medium — The round-trip audit normally passes even when edits are rejected.**
   - Problem: Edit failures are counted and printed, but the failure-rate assertion runs only with `AUDIT_ASSERT=1`. Default test runs assert identity and can miss a regression that makes ordinary edits unusable.
   - Evidence: `test/roundtrip_audit_test.dart:248`, `:260`, `:264`, `:265`.
   - Smallest fix: Always assert the synthetic edit corpus's expected results. Keep external-vault sweeps opt-in and separate from that deterministic gate.

### Nice to have

16. **Low — Large methods still combine independent jobs after the file splits.**
   - Problem: The 935-line app build assembles several screens; the 879-line path-sync function combines conflict repair, bootstrap, transfer, and deletion policy. A file move alone does not make those branches easier to review.
   - Evidence: `lib/app_mobile.dart:4285`; `lib/nextcloud_sync/path_sync.dart:228`; `lib/nextcloud_sync.dart:428`; size inventories below give exact inclusive spans.
   - Smallest fix: Move existing screen sections into the existing widgets, and keep sync decision policy separate from executing transfers. Start with a self-contained job; do not add interfaces or split solely to meet a line limit.

17. **Low — Three public Vault aliases have test callers but no production callers.**
   - Problem: `dailyNote`, `project`, and `article` add API names while forwarding directly to existing operations. Whole-repo source searches found their calls only in tests, so tests maintain API the app and CLI do not use.
   - Evidence: `lib/vault.dart:150`, `:216`, `:219`; callers at `test/vault_test.dart:274`, `:325`, and `test/journal_feed_test.dart:79`.
   - Smallest fix: Delete the aliases and use `todayNote(day)` or `page(..., kind: ...)` in those tests. Do not remove core-package export shims, which intentionally expose package entry points.

18. **Low — Inline autocomplete has a hard-coded switch with no configurable caller.**
   - Problem: The public constant is always true and only guards listener attachment/removal. It is not a user setting or environment flag, so the false path adds maintenance without a selectable configuration.
   - Evidence: `lib/rich_editor/document_model.dart:5`; its only references are `lib/rich_editor/editor_widgets.dart:149` and `:854`.
   - Smallest fix: Delete the constant and both conditions. A future emergency change can disable the feature at the same call sites.

19. **Low — The metadata audit reports a pass when its required vault is unavailable.**
   - Problem: Missing opt-in configuration or the expected vault prints a message and returns normally. Test summaries cannot distinguish this from a completed audit.
   - Evidence: `test/metadata_audit_test.dart:39` through `:49`.
   - Smallest fix: Use `markTestSkipped` for the missing prerequisites, as the compiler test already does at `packages/tylog_core/test/writer_compiles_test.dart:31`. Keep its private-vault input opt-in.

## Limits and verdict

Known, documented limits were not promoted into findings without evidence that the assumed load crosses them: the non-atomic lock with no heartbeat (`lib/vault_lock.dart:11`) and in-memory portable export (`lib/database/portable_snapshot.dart:73`). Large-download buffering was ranked separately because it runs directly on foreground sync. Existing worker indexing (`lib/vault_worker.dart:36`) and background SQLite opening (`lib/database/tylog_database.dart:1285`) already move important work away from the UI isolate.

This is source-confirmed static review, not runtime reproduction. Deep reads focused on save/read ownership, conflict resolution, transfer helpers, database revision handling, editor replacement/serialization, lifecycle, and background completion. Import, graph, PDF, native compiler, platform storage internals, and all test bodies were not exhaustively audited. No test execution, hardware frame measurements, full-suite run, network verification, or external-vault inspection occurred. No credentials were printed.
