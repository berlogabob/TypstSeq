
1. **[P1] Organization projects can be modified outside the allowed ownership boundary** — [github_projects.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/github/github_projects.dart:52) lists organization projects with read access, and the board attempts Status mutations on any selected project. An editable project owned by another team can therefore be changed. Restrict mutations to projects verified as the user’s own, and enforce that check when loading or moving a card, not only in the picker.

2. **[P1] External links stop working when codes or tags change** — [olt_connector.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/connectors/olt_connector.dart:24) uses a place’s mutable code as its ID and an asset’s mutable tag as its ID. Changing either, or adding a code to a place that lacked one, breaks existing note links and `part_of` relationships. Use immutable source row IDs as entity IDs, keep codes and tags as aliases, and migrate already-written references.

3. **[P1] References to external entities resolve as missing notes** — [workspace_controller.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/workspace_controller.dart:300) updates the merged entity list without updating `workspace.linkResolver`, which is built from vault notes alone. Tapping a note reference to an OLT ID consequently offers to create a local note instead of opening the entity. Build the resolver from the merged index and refresh it when either source changes.

4. **[P1] OLT results are silently truncated at the API row limit** — [olt_cache.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/olt/olt_cache.dart:70) fetches each table in a single unpaged request. With the usual PostgREST 1,000-row limit, larger inventories lose assets, locations, items, or stock from the cache and display incomplete results as current. Fetch stable, ordered pages until each table is complete before replacing the cache.

5. **[P2] Signing out hides the existing cache** — [app_mobile.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/app_mobile.dart:469) returns before loading cached data when no session exists. After sign-out and restart, previously cached entities disappear with no sign-in message. Load the device cache first, retain it on authentication failure, and show that sign-in is needed; also map expired refresh-token failures to that state.

6. **[P2] Failed refreshes leave old data looking current** — [app_mobile.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/app_mobile.dart:496) silently suppresses network, permission, and server errors after loading the cache. Users cannot tell that displayed stock or asset locations are stale, and a failure fetching any new table also prevents the other tables from refreshing. Surface the failure and last successful refresh time while retaining the cache.

7. **[P2] Concurrent actions can lose Decision records** — [github_project_board.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/widgets/github_project_board.dart:51) reads and rewrites a shared `github.jsonl` file after a move. Another device or the existing GitHub issue flow can write the same file concurrently, overwriting one of the required records. Write to the per-device ledger and serialize local ledger updates.

8. **[P2] Every index access rebuilds all external entities on the UI thread** — [workspace_controller.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/workspace_controller.dart:306) copies the entire vault map and constructs a new `NoteRef` for every external entity on each getter call. Ordinary builds access this getter repeatedly, so thousands of assets cause repeated allocations and work during interaction. Memoize the merged index and invalidate it only when the vault index or external entities change.

9. **[P2] Building place entities repeatedly scans all stock rows** — [olt_connector.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/connectors/olt_connector.dart:55) scans the full stock list once per place, on the UI isolate, for both cached and refreshed data. Large inventories therefore take time proportional to places multiplied by stock rows. Group stock by `place_id` once, then attach each place’s rows from that map.
