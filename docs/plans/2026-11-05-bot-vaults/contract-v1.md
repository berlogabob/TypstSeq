# Bot vault handoff, schema 1

The TyLog build at e21e62a checks only that `bot-vault.json` is an object with integer `schema: 1`, then mounts `.typ` files read-only. It does not produce or consume the outbox described below. This document specifies the first producer-side convention for the remaining P6a-rest work; it is not a claim that that work is implemented.

The bot owns a separate private directory. Its manifest is `{"schema": 1, "bot": "amadora-news"}`; `bot` and unknown keys are optional and preserved. A manifest with a different schema must not be modified. The bot writes UTF-8 Typst notes under `items/` and source entities under `entities/`, using the managed TyLog header and the host vault's `/_system/tylog.typ` package, as in `docs/vault-format.md`. Item IDs are `item-` plus the lowercase SHA-256 hex digest of the exact source link encoded as UTF-8; source entity IDs use `source-` and the digest of the exact source name. Paths are `<directory>/<id>.typ`. Items contain the feed title and source snippet when captured, source name, URL and generated draft; entity notes have kind `website`. Notes are created once and existing notes are never overwritten. The bot can export currently pending articles with only fields retained in its state; it does not backfill old articles or export digest drafts. New notes represent drafted or automatically posted items, not every candidate. Feed snippets are not full source articles and no profile, rule or prompt version is currently captured.

An outbox producer may append UTF-8 JSON objects, one complete line per decision, to `outbox/decisions.jsonl`. Each record has integer `schema: 1`, nonempty string `id` (globally unique event ID), `item_id` matching an exported item, nonempty string `at` (UTC ISO-8601 timestamp), and `action` of `accepted`, `rejected`, or `dismissed`. Unknown keys are retained in the bot's receipt. The writer must append a trailing newline, keep previous rows and reuse the same ID on retries. The bot ignores malformed, incomplete, unsupported, and unknown-item rows, rereads the file, and stores the first valid event for each ID in `bot_vault_decisions` in its own state. Unrecognized or incomplete rows may be retried after correction; the outbox is never deleted or rewritten by the bot. Events are advisory only: no outbox decision changes pending drafts, queue, or Telegram posting. The bot logs vault errors and continues normal posting. Vault access and any synchronization must be restricted appropriately for draft and source content.

This convention leaves readiness assessment, applying decisions, concurrent outbox writers, isolated indexing, and Android access to P6a-rest. Compilation requires a TyLog package installed in the host vault; the bot does not manufacture a vault marker or package files.
