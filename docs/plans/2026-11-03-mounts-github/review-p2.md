# P2 review findings (codex terra, 2026-11-03)

1. **[P1] Cache and outbox are shared across vaults** — [workspace_controller.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/workspace_controller.dart:116) keys both directories only by mount ID, although IDs are unique only within a vault. Two vaults with the same ID can load each other’s cached notes and pending edits; a push can send those edits to the second vault’s repository. Namespace both by stable vault identity and bind entries to the mount’s repository and ref.

2. **[P1] Refresh can erase a saved edit** — [mount_fetcher.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/github/mount_fetcher.dart:84) snapshots the outbox before swapping directories. A save after that snapshot can write to the old cache and enqueue successfully, then the swap deletes the edited file. Serialize saves, refreshes, pushes and conflict resolution per mount, preserving pending files under the same lock through the swap.

3. **[P1] Interrupted cache swaps can discard the backup** — [mount_fetcher.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/github/mount_fetcher.dart:117) deletes an existing `.old` directory before checking whether the target exists. If the app stopped after renaming the target to `.old`, the next refresh deletes the only old cache, including pending edits. Recover an orphaned backup before starting a new swap and retain it until the replacement is durable.

4. **[P1] Repeated saves create conflicts with the app’s own push** — [github_outbox.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/github/github_outbox.dart:114) queues multiple entries with the same base SHA, but each push reads the latest cache bytes. The first entry pushes those bytes; the second uses the old SHA and conflicts with that push. Coalesce pending entries per path or atomically advance successor base SHAs, including edits arriving during upload.

5. **[P1] Duplicate issue lines can share the wrong GitHub issue** — [send_issue.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/github/send_issue.dart:41) identifies recovery records by note path and line text. Two identical lines in one note therefore receive the same issue number; syncing either can close or update the other’s issue. Give each issue a durable distinct identifier and use it for recovery and search.

6. **[P2] Folder mounts can block vault opening** — [workspace_controller.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/workspace_controller.dart:716) awaits mount loading before publishing the usable vault, and [the loader](/Users/berloga/Documents/GitHub/TypstSeq/lib/workspace_controller.dart:1023) awaits filesystem probes and directory listing for every mount. A stalled removable or network directory can prevent the editor from opening. Defer mount probing and indexing until after the fast path, with bounded failure handling.

7. **[P2] GitHub sign-in is unreachable** — [github_auth.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/github/github_auth.dart:74) implements device authorization but has no production caller or settings flow. Android has no `gh` fallback, so users cannot authenticate for private mounts, pushes or issues. Add the device-code sign-in and sign-out flow to settings.

8. **[P2] Mount refresh retains stale credentials** — [workspace_controller.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/workspace_controller.dart:122) caches a fetcher with the token obtained at its first creation. Signing in, signing out or changing credentials does not affect later refreshes. Resolve credentials for each refresh or invalidate the fetcher when authentication changes.

9. **[P2] Update can install an unverified replacement pack** — [module_flow.dart](/Users/berloga/Documents/GitHub/TypstSeq/lib/app_mobile/module_flow.dart:154) downloads the latest release again after the update check, without verifying its module ID or version. If the release changes in between, Update can install a different module or downgrade the existing one. Install the previously verified pack, or revalidate its ID and version immediately before installation.
